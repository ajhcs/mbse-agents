## Defects

### F1 — P1: answer length gives away almost every single-choice key

Across 55 single-choice items, `max(choices, key=lambda option: len(choices[option]))` matches 54 keys. The one exception is SEJ-013. Counts by split are 21/21 practice, 21/22 development and 12/12 evaluation-public. Applying the same one-option rule to every question gives 54/60 overall with no knowledge of the scenario. Exact item-level results are in [choice-shortcuts.json](benchmark-independent/choice-shortcuts.json).

The correct option routinely contains the complete, qualified engineering procedure while alternatives are short absolutes, irrelevant activities or plainly unsupported claims. Examples include SEJ-046's long evidence/decision explanation versus a definition, jargon and an unsupported unsafe declaration; SEJ-049's state/authority view versus supplier names, alphabetical functions and an enclosure rendering. Balanced answer-letter frequencies do not repair this content cue.

Revise the bank as a new version. Give each option a plausible engineering action of comparable detail, with a concrete supplied fact making one preferable. Do not merely pad distractors to equal length. Recheck the validity and uniqueness of the key after every rewrite. Selection accuracy from the original bank remains a diagnostic of these particular questions, not evidence of an improvement in reasoning.

### F2 — P2: answers are not bound to the packet actually answered

The response template at original `scripts/benchmark.py:160-166` includes no packet identity or digest. `score()` validates the supplied packet and the answer IDs separately (`206-234`), then takes `arm` from whichever packet was passed (`250-253`). The same unchanged synthetic answer file and same review were accepted against both `none` and `task-domain` packets. Each result claimed its supplied arm.

This permits accidental cross-arm or cross-version misattribution without any edits to the answer file. Bind responses to the exact input packet through an immutable packet identifier plus hashes, or a manifest digest recorded in the response. Validate it before scoring. Existing unbound outputs need an explicit legacy status; do not backfill an execution binding as if the producer supplied it.

### F3 — P2: an unchanged review can be applied to a different rubric

Original `scripts/benchmark.py:262-281` binds a review only to answer bytes and the number of criteria. Ratings are positional arrays. In the probe, a new versioned bank/key reversed SEJ-001's two reasoning criteria. The original answer file and review `[2,0]` were accepted against the new packet, silently assigning each rating to the other criterion. See `score-new-rubric.json` under the probe artifacts.

Bind reviews to the exact key/criteria revision and packet, preferably using stable criterion identities as well as a digest. Reordering or changing a criterion must require a new assessment or an explicit adjudicated migration. Answer-byte integrity alone is insufficient for review applicability.

### F4 — P2: packet verification accepts structurally incomplete or contradictory manifests

Original `verify_packet()` (`183-203`) iterates whatever `files` entries remain but does not require the request/template hashes or reconcile arm, skill inventory and installed packages. Two probes were accepted: remove `request.md` from the manifest and materially change the request; relabel a no-skill packet `catalog` while retaining `skills: []` and no skill directory.

Require the complete mandatory input inventory, distinct selected questions, valid packet identities, and internally consistent arm/package metadata. Compare actual selected input files against that inventory. A local mutable manifest is not an authenticity or isolation boundary; these are consistency checks to catch malformed records, not a claim that a malicious controller cannot forge a packet.

### F5 — P2: the comparison report trusts impossible summary values

Original `report()` (`289-304`) checks top-level schema/kind, matching bank/key/question identities and distinct run IDs, then copies `selection_accuracy` without checking it against outcomes. A one-item score with a single correct outcome was changed only to a new run ID and `selection_accuracy: 7.0`; `report()` accepted it and displayed the two accuracies as `1.0` and `7.0`.

Validate full score structure and recompute or cross-check counts, per-dimension aggregates and derived accuracy before reporting. Retain the input score identities/digests in the report. This can detect inconsistency, although external provenance still requires the bound source artifacts.

### F6 — P2: two multiple-selection keys confuse consideration with adoption

SEJ-008 (`items.json:257`, `keys.json:78`) asks which *issues belong in the lifecycle review*. Option A is “Whether every module should be physically destroyed on replacement.” Reviewing whether destruction is necessary is reasonable for retired credential-bearing hardware; a reviewer can conclude it is unnecessary. The rationale rejects prescribing destruction, which is not what A says. The key B/C/D is therefore not uniquely justified as written.

SEJ-027 (`items.json:658`, `keys.json:271`) asks which interface conditions *matter before executing* a delayed command. Option C asks whether the signature was valid when sent. The scenario grants a valid signature, so this may be redundant, but it does not make signature validity irrelevant. The key A/B/D needs a stem such as “which additional conditions remain unresolved,” or a distractor that explicitly claims signature validity is sufficient for execution. The current all-or-nothing scoring can penalize defensible A/B/C/D answers.

These are wording/key-adjudication defects, not demands that every possible interpretation receive full credit. Preserve the original versions and adjudicate any affected old responses against their original wording.

### F7 — P2: HO-04's timing rubric omits its composition assumption

The HO-04 request gives interface processing “up to 150 ms,” detector 80 ms and actuator 30 ms. Its first rubric requires recognizing that 260 ms exceeds 200 ms. The request does not state that stages are serial/nonoverlapping or that their maxima can coincide. The sum is a conservative bound under a serial model; a bound exceeding the target is a support/allocation gap, not an observation of implementation failure.

Reward an explicit conditional composition argument or supply the intended serial/nonoverlap assumption. HO-13's architecture fixture already supplies that assumption and its rubric separately distinguishes missing evidence from demonstrated failure. Carry that precision into HO-04.

### F8 — P3: the Flight 1549 simulation locator points partly to the wrong section

The HG-08 source map and HO-16 request cite NTSB/AAR-10/03 §§1.16.1 and 2.3.2. The immediate-return versus delayed-return simulation setup is §1.16.3, printed pp49–50; §2.3.2, pp88–89, supplies the interpretation. §1.16.1 is the airplane performance study. The fact and key are supported, but the first locator should be corrected in a versioned source update. [NTSB report](https://www.ntsb.gov/investigations/AccidentReports/Reports/AAR1003.pdf).

### F9 — P3: score-output preservation does not refuse dangling symlinks

Original CLI `score --output` checks `.exists()` (`359-363`), unlike packet preparation's additional `.is_symlink()` check. A dangling output symlink passes that guard, then `write_json()` creates the symlink target. The local synthetic probe confirmed this behavior. Refuse symlinks as existing outputs and use an exclusive write if concurrent creation must be protected. This is a small consistency repair; no production file was affected.

## Coverage, packet separation and pedagogical improvements

The bank covers twelve useful systems-engineering dimensions, with 24 practice, 24 development and 12 public-evaluation items. It emphasizes causal dependencies, semantic interfaces, evidence applicability, lifecycle/human support and decision authority. That is substantive engineering content. It contains little quantitative derivation beyond a Boolean cut-set item; alternatives usually differ in generic good practice rather than close, competing mechanisms. This limits discrimination even after length cues are removed. Add a small number of tractable allocation, uncertainty, resource, sequencing and sensitivity problems when the intended workload justifies them. This is an improvement suggestion, not a correctness defect in the present keys.

The selected packets omit `keys.json`, `rubrics.json` and previous output files; the 17 tests confirm this for their exercised paths. Copied skill references may legitimately teach relevant concepts. Packet separation is not protection against a participant with access to the public repository, its known keys or another run. The documentation explicitly says so and appropriately calls for fresh variants after exposure. It does not overstate the reserved public split as secret or leak-proof.

HO-13 is the strongest concrete performance fixture: immutable source wording, protected operator note, retained IDs, conflicting recovery behavior, a changed timing criterion and an explicitly historical synthetic observation. The old observation is not presented as a repository-executed controller test. The requirement change does not establish implementation compliance. A reviewer should also notice that the historical observation and current timing allocation are not automatically measurements of the same setup; the fixture says detailed historical setup/uncertainty are unavailable.

The performance rubrics generally reward located consequences and preserve uncertainty. HO-08 supplies a useful negative activation task. HO-09–12 cover concept, intended-function limitations, organizational authority and concise problem framing. HO-14–19 separate source facts from transfer claims. HO-20 is a benign, clearly bounded instruction-in-evidence test. Aside from F7, no categorical rubric-key error was established. More rubric examples showing partial versus complete reasoning could improve reviewer consistency; this would need independent adjudication rather than author self-certification.

The documents correctly reserve agent-quality claims for actual independent performance evidence and state that passing maintenance tests does not demonstrate model quality. Preserve that distinction through the repair. A revised bank needs its own version, input hashes, independent key review and fresh participant evidence. Original run records must remain attached to their original bank/key/scorer revision.
