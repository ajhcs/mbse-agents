| MD-01: “FDA Class III/PMA under 21 CFR 876.5820” | Wrong device regulation. Section 876.5820 identifies a hemodialysis system. Section 880.5725 identifies a healthcare-facility infusion pump and specifies Class II. Use the latter as the provisional starting point for this external large-volume IV pump. [Current eCFR, 880.5725(a)–(b)](https://www.ecfr.gov/current/title-21/chapter-I/subchapter-H/part-880/subpart-F/section-880.5725), [876.5820(a)](https://www.ecfr.gov/current/title-21/chapter-I/subchapter-H/part-876/subpart-F/section-876.5820). | Regulatory lead: controlled intended-use and device/system boundary, product-code assessment, technological characteristics, predicate and substantial-equivalence assessment. A Class II starting point is not a completed 510(k) determination. |
| MD-02: “EU IIb under Rule 11” | IIb is a plausible conclusion with the wrong principal rationale. Rule 12 addresses active administration/removal of substances: potentially hazardous administration leads to IIb; the current guidance lists infusion pumps. Rule 11 concerns software. Software driving/influencing the pump also requires consideration of Annex VIII implementing rule 3.3. [MDCG 2021-24 Rev.1, April 2026, printed pp. 47–48](https://health.ec.europa.eu/system/files/2021-10/mdcg_2021-24_en_0.pdf). | Regulatory lead: justify hazardous administration from intended substances, IV route, patient population and mode of application; assess all applicable rules and system/software boundaries, including any separately marketed software. Record the manufacturer's rationale and applicable conformity-assessment review. |
| MD-03: “IEC 62304 C because FDA Class III” | Invalid mapping. Product class and software safety class are separate decisions. Class C may be supportable if the software-related hazardous situations can lead to death or serious injury under the applicable classification method, but no such risk analysis was supplied. | Software safety/risk leads: identify software contributions to excessive, inadequate or unintended delivery and loss of protective functions; evaluate resulting harms, external risk controls, architecture/segregation, and the adopted edition's classification method. Record a justified software class independently of FDA class. |

Two boundaries matter. FDA's infusion-pump guidance explicitly recognizes pumps submitted as part of a Class III system as a PMA case; nothing supplied establishes that system context here. Its current cover notice also distinguishes FDA software submission **Documentation Level**, generally Enhanced for infusion pumps, from device classification. Neither fixes the IEC software class. [FDA, *Infusion Pumps Total Product Life Cycle*, 2014, section 3 and current cover notice](https://www.fda.gov/media/78369/download).

For EU Rule 22, local feedback maintaining a clinician-set flow is not, by itself, an incorporated diagnostic function significantly determining patient management. The supplied absence of physiological diagnostic control gives no affirmative basis for Rule 22 Class III. Reopen that assessment if the device uses patient measurements to adapt therapy. [MDCG 2021-24 Rev.1, printed p. 59](https://health.ec.europa.eu/system/files/2021-10/mdcg_2021-24_en_0.pdf).
